# 모델 지침 (공수 기반 배분)

## 원칙
| 모델 | 맡는 일 | 판단 기준 |
|---|---|---|
| **Opus 5.5** | 결정·설계·검토 | 결과가 이후 단계 전체를 바꾸는가? (컨셉 선택, 전략 종합, 레드팀, 게이트 검토) |
| **Sonnet 5.5** | 실행·초안·수집 | 틀이 정해져 있고 채우는 일인가? (웹 리서치, 표 작성, 스킬 양식 채우기, 문서화, 덱) |
| **Haiku 5.5** | 단순 변환 | 생각 없이 옮기는 일인가? (읽는순서 갱신, 파일명 정리, 표 포맷 변환, 출처 목록 정렬) |

애매하면 Sonnet으로 초안 → Opus로 검토 (2단).

## 실행 방법
- **세션 전체 전환**: 앱 모델 선택기에서 단계 성격에 맞게 선택
  - 01 시장조사 수집, 04 캘린더, 05 브랜드북 문서화 → Sonnet 세션
  - 02 컨셉 결정, 03 레드팀, 모든 게이트 검토 → Opus 세션
- **Opus 세션에서 위임**: Agent 도구 `model: "sonnet"`(또는 `"haiku"`)로 서브에이전트 실행, 결론·파일 경로만 받기
  - 예: "01_시장조사/README의 1-2를 source-research-report 스킬로 수행해 `시장동향_v0.md`로 저장. 결과는 인사이트 3줄만 보고"
- 서브에이전트 프롬프트엔 반드시: 읽을 파일 경로 · 사용할 스킬 · 저장 파일명 · 보고 형식
